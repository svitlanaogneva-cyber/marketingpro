# Заявки з сайту → Google Sheets

Сайт (Vercel, `POST /api/lead`) перевіряє й збагачує заявку та передає її в Apps Script, який живе
всередині таблиці й дописує рядок. Сервісні акаунти, Google Cloud і шарінг таблиці не потрібні.

```
форма → /api/lead (перевірка Origin, honeypot, ліміт, очищення, UTM/пристрій/гео)
      → Apps Script Web App (перевірка секрету, замок, дедуплікація за ID) → аркуш «Заявки»
```

## Одноразове налаштування (робить власник таблиці)

1. Таблиця → **Розширення → Apps Script** → видаліть усе в `Код.gs` і вставте вміст `Code.gs` з цієї теки → **Зберегти**.
2. Угорі виберіть функцію **`setup`** → **Запустити**. Google попросить дозволи: це власний скрипт, тому попередження
   «додаток не перевірено» нормальне: **Додатково → Перейти на сторінку… (небезпечно) → Дозволити**
   (скрипт має `@OnlyCurrentDoc`, тобто бачить лише цю таблицю).
3. У таблиці зʼявляться аркуші **«Заявки»** та **«Аналітика»** і вікно з **секретом** — скопіюйте його.
4. **Ввести в дію → Нове розгортання → Веб-застосунок**: «Виконувати від імені» — *Я*, «Хто має доступ» — *Усі*
   → **Ввести в дію** → скопіюйте URL, що закінчується на `/exec`.
5. Vercel → Project → **Settings → Environment Variables** (Production і Preview):
   - `LEAD_WEBHOOK_URL` = URL з кроку 4
   - `LEAD_WEBHOOK_SECRET` = секрет з кроку 3

   → **Redeploy**.
6. Перевірка: у таблиці меню **marketingpro → Додати тестову заявку**, потім відправте форму на сайті.

> Секрет зберігається у **Властивостях скрипта** (⚙ Налаштування проєкту → Script properties → `LEAD_SECRET`)
> і в Vercel. У код, таблицю й git він не потрапляє. Замінити: змініть значення в обох місцях.

## Демо-дані й графіки

Меню **marketingpro → Додати демо-дані (80 заявок)** генерує вигадані заявки за 30 днів (різні джерела, кампанії,
статуси, курси, пристрої) — щоб побачити таблицю, фільтри й «Аналітику» в дії. ID таких рядків починається з `TEST`,
тож вони прибираються кнопкою «Видалити тестові заявки».

Аркуш **«Аналітика»** містить п'ять графіків: заявки по днях (30 днів), статуси (бублик), джерела, кампанії
і сторінки, з яких прийшли заявки. Дані для двох із них рахуються в службових колонках `W:AB` праворуч.

## Прибрати тестові заявки

Меню **marketingpro → Видалити тестові заявки**: видаляє лише рядки з ID `TEST…` або джерелом `test`
(тестова заявка з меню, перевірки вебхука); справжні заявки не чіпає. «Аналітика» перераховується сама.

Вручну: увімкніть фільтр по колонці (наприклад, «Ім’я» = Тест), виділіть видимі рядки → правий клік →
**Видалити рядки**. Після ручного видалення багатьох рядків запустіть **Налаштувати / оновити оформлення**.

## Оновлення скрипта

Змінили `Code.gs` → вставте новий код → **Ввести в дію → Керувати розгортаннями → ✏️ → Версія: Нова → Ввести в дію**.
URL при цьому не змінюється. Після зміни `COLUMNS` запустіть **marketingpro → Налаштувати / оновити оформлення**
(дані заявок не чіпає; але якщо додали колонку посередині, існуючі рядки треба зсунути вручну).

## Що зберігається

Усі назви колонок написані простою мовою, а **при наведенні на заголовок показується підказка**, що це за колонка.
Поля форм названі так само, як на сайті.

**На виду (14 колонок):** коли надійшла заявка (Київ), статус (список: Новий → Зв’язались → В роботі → Клієнт / Відмова / Спам),
тип заявки (Консультація / Академія), **Цікавить навчання?**, **Імʼя**, **Телефон або Telegram для звʼязку** (Telegram-нік клікабельний),
**Лінк на Instagram або сайт** (клікабельний), **Ніша бізнесу**, наскільки заповнена заявка (Повна / Часткова / Лише контакт),
звідки прийшла людина, з якої реклами, а також три колонки для команди: **Відповідальний**, **Наступний контакт**, **Коментар менеджера**.

**Згорнуті службові (натисніть «+» над літерами колонок):** номер заявки; дата, тиждень і місяць (для фільтрів);
де заповнили форму й адреса сторінки; тип джерела, яке оголошення, аудиторія; код рекламного кліку; з якого сайту прийшли;
з якої сторінки почали; переглянуті кейси, скільки сторінок і часу до заявки; перший чи повторний візит і дата першого візиту;
країна / регіон / місто; пристрій і браузер; мова, часовий пояс, розмір екрана; технічні мітки Meta (для майбутнього Pixel);
відбиток адреси (пошук спаму; саму адресу не зберігаємо); технічний опис браузера.

**«Звідки прийшла людина»** визначається автоматично: мітка реклами (`utm_source`) → рекламний клік Meta/Google/TikTok →
сайт-реферер → застосунок (Instagram/Facebook/Telegram) → прямий візит. Мітки запамʼятовуються на весь візит: людина могла прийти
з реклами, походити сайтом і залишити заявку на іншій сторінці.

Відповідність колонок і полів сайту перевіряє автоматичний тест (`tests/sheet-columns.test.ts`): якщо на сайті зʼявиться нове поле
без колонки в таблиці, CI стане червоним.

## Гнучкість: що можна змінювати

Скрипт знаходить колонки й аркуші за **внутрішніми мітками**, які рухаються разом з ними, тому таблицю можна вільно міняти:

- переставляти, вставляти, ховати й видаляти колонки; додавати свої колонки де завгодно;
- перейменовувати заголовки й аркуші («Заявки», «Аналітика», «Інструкція»);
- видаляти, переміщувати й сортувати рядки, лишати порожні рядки між заявками;
- міняти статуси (додавати свої, міняти кольори), шрифти, ширину, фільтри.

Обережно лише з трьома речами: не видаляти колонку **«Телефон або Telegram для звʼязку»** (без неї запис завершується помилкою й заявка лишається
в журналі Vercel), не перейменовувати статуси «Новий» / «Клієнт» / «Спам» (від них залежить «Аналітика»), не видаляти «Номер заявки» (захист від дублів).
Після переставлення колонок: меню **marketingpro → Оновити аналітику й інструкцію**. **Скинути оформлення до стандартного** повертає
заголовки, кольори й список статусів, але не чіпає заявки й порядок колонок.

## Вкладки

| Вкладка | Що там | Перезаписується скриптом |
|---|---|---|
| Заявки | сама таблиця | ні (лише «Скинути оформлення» — вигляд, не дані) |
| Аналітика | цифри й 5 графіків | так, при «Оновити аналітику й інструкцію» |
| Інструкція | пояснення простими словами: що можна, що звідки береться, як заповнюється кожне поле | так, при оновленні |
| Технічні дані | акаунти (GitHub, Vercel, Google, домен), де лежать секрети й змінні, типові дії при поломці, відкриті правки з ТЗ | **ні**: заповнюється вручну |

## Зручність роботи

- Фільтр на всіх колонках (шапка), шапка й перші 2 колонки (дата, статус) закріплені.
- **marketingpro → Нові зверху** — один клік сортує за датою від нових до старих (автоматично не сортуємо, щоб рядки не «тікали»).
- Аркуш **«Аналітика»** (формули, оновлюється сам): заявки сьогодні / 7 / 30 днів, нові без обробки, клієнти й конверсія,
  розрізи за джерелом, кампанією, курсом, сторінкою, типом і по днях.
- Статуси підсвічуються кольором, «Відмова» і «Спам» приглушуються.

## Надійність і безпека

- Секрет порівнюється без раннього виходу; без нього скрипт відповідає `forbidden`.
- Запис під `LockService` — одночасні заявки не потрапляють в один рядок.
- ID заявки генерується в браузері один раз на форму: повторна відправка (подвійний клік, ретрай) не створює дубль.
- Усі значення пишуться в клітинки з форматом «звичайний текст»: `=формули` не виконуються, телефон не стає числом.
- Якщо Sheets недоступний — сайт двічі пробує, показує людині повідомлення з Telegram-запасом,
  а повна заявка лишається в логах Vercel (`[lead:FAILED]`), її можна внести вручну.
- Сайт приймає POST лише з власного Origin, відсікає ботів через honeypot, обмежує частоту й розмір запиту.
- Персональні дані (імʼя, контакт) потрапляють у вашу таблицю: доступ до неї визначаєте ви.
  Якщо на сайті є відвідувачі з ЄС, додайте на сайт політику конфіденційності.

## Локальна перевірка без Google

`LEAD_WEBHOOK_URL=http://localhost:4010/exec LEAD_WEBHOOK_SECRET=test npm run dev` + будь-який мок-сервер,
що приймає `POST {secret, lead}` і повертає `{"ok":true}` (з редіректом 302, як справжній Apps Script).
